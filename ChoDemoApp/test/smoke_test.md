## 阶段二：API 层单元测试

### 测试 1: 登录接口格式 (JSON)

**测试目的**: 验证登录接口使用 JSON 格式而非 form-urlencoded

**测试步骤**:
1. 使用无效账号尝试登录
2. 抓包或使用日志查看请求格式

**预期结果**:
```json
POST /api/v1/auth/login
Content-Type: application/json

{"username":"test","password":"test123"}
```

**通过标准**: 返回 401（账号不存在）而非 422（格式错误）

---

### 测试 2: 创建日程带 type/priority

**测试目的**: 验证 type 和 priority 作为独立字段发送

**测试步骤**:
1. 登录账号
2. 创建一个工作类型的高优先级日程
3. 查看请求体

**预期结果**:
```json
POST /api/v1/events/
{
  "title": "测试会议",
  "start_time": "2026-03-12T10:00:00+08:00",
  "end_time": "2026-03-12T11:00:00+08:00",
  "type": "WORK",
  "priority": 3
}
```

**通过标准**: 
- 响应 201 Created
- 响应中包含 `"type": "WORK"` 和 `"priority": 3`
- 不再需要在 description 中塞 JSON meta

## 常见问题排查

### 问题 1: 登录返回 422
**原因**: 后端可能仍期望 form-urlencoded
**解决**: 确认后端已更新到 openapi2 版本

### 问题 2: type/priority 不生效
**原因**: 后端可能未实现这两个字段
**解决**: 检查后端 EventBase 模型是否有 type/priority

### 问题 3: 日历颜色标记不显示
**原因**: remoteEventToEntity 解析问题
**解决**: 检查日志，确认 ev.type 和 ev.priority 有值
